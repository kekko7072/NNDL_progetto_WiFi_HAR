\section{Processing Pipeline}
\label{sec:processing_architecture}

All of our models cast Wi-Fi HAR as the classification of Doppler-spectrogram
images and share the same data front-end. They differ in how the
representation is learned and in how the per-window decisions are
combined. The raw CSI Doppler traces are cut into fixed-size
windows of shape $1\times340\times100$, one antenna at a time.
From there the pipeline forks:
\begin{itemize}
  \item the \textbf{baseline chain} feeds each window to an
  Inception-style CNN trained end-to-end with cross-entropy, and reads the
  activity off the softmax output;
  \item the \textbf{contrastive chain} first applies
  domain-randomization augmentations to build two views of each window, pre-trains
  a deeper batch-normalized encoder with a Supervised Contrastive loss, then
  freezes the encoder and fits a linear probe on the resulting features;
  \item the \textbf{fusion stage} sits after either classifier and needs
  no retraining: the per-antenna class probabilities of the same physical time
  window are averaged into one decision.
\end{itemize}
All chains are trained on a single environment ($S1$) and evaluated under the
same cross-domain protocol (unseen $S2$--$S7$), so they can be compared on equal
footing against the reference SHARP system~\cite{sharp} 
(\secref{sec:learning_framework} details them).

\subsection{The changes we evaluate}
\label{sec:versions}
Four modifications were implemented on that skeleton, each isolated so that its
effect is attributable (\tab{tab:versions}): a windowing strategy, a
group-aware pipeline enabling decision fusion, a contrastive
representation and an optimizer schedule. Only the first touches the data
loader and only the third trains a new network. Fusion is post-processing on an
unchanged model, which is what makes its gain remarkable. The sliding window and 
fusion compose into our best configuration.

\section{Signals and Features}
\label{sec:model}
% (Dataset pipeline implemented by M.~Carraro.)

\subsection{The SHARP data}
We use the pre-extracted Doppler traces released with the SHARP
dataset~\cite{csidataset} (IEEE~802.11ac, $80$\,MHz): arrays of shape $(T,100)$
($T$ time steps, $100$ Doppler-velocity bins) one per receiving antenna
(\texttt{stream\_1}\dots\texttt{stream\_4}) of a four-antenna monitor. They map to
seven measurement sets $S1$--$S7$, each a distinct (environment, monitor
position, person, day) combination. Only $S1$ is used for training, instead the others
explore generalization to an unseen day ($S2$), an unseen person ($S3$), blocked
line-of-sight ($S4$, $S5$), a different room ($S6$), and new room, day and person
at once ($S7$).

\subsection{From traces to windows}
We use the five core activities present in every environment: \textbf{E} (empty
room), \textbf{J} (jumping), \textbf{L} (sitting still), \textbf{R} (running),
\textbf{W} (walking), matching the five-class task of~\cite{sharp}. Each trace
is cut into windows of $W_{\text{len}}=340$ time samples ($\approx 2$\,s)
advancing by a stride $S$, plus a channel dimension with inputs of shape
$1\times340\times100$. Each antenna stream is an independent labelled sample, as
SHARP does at training time. The antenna identity is re-used only at decision
time (\secref{sec:fusion}).

\textbf{Windowing strategy.} The reference configuration uses
$S=W_{\text{len}}=340$, i.e.\ non-overlapping windows: simplest, but
wasteful. A trace of length $T$ yields only $\lfloor T/340\rfloor$ examples and
any pattern straddling a boundary is cut in half. The alternative is a
sliding window: after prototyping $S=170$ we adopted $S=30$, the value hard-coded
in the SHARP authors' own dataset script, $91\%$ overlap and $152{,}320$ windows
from the same recordings. They are strongly correlated, so the number of
independent examples grows far less than tenfold, and a window and its
neighbour can fall on opposite sides of the random train/val split, making the
validation loss optimistic and perturbing when early stopping fires. The
test figures are unaffected.

\textbf{Group identifiers.} The four streams of a recording have identical
length, so window~$k$ of each starts at sample $kS$ of the same event. The parser
therefore keeps the full recording token (\texttt{"J2"}, repetition number
included) and the loader emits a group id \texttt{env\_token\_k} per window:
windows sharing it are the same physical time window seen by different antennas,
which is what makes \secref{sec:fusion} possible. The id travels through the
split with the labels, and the test \texttt{DataLoader} uses
\texttt{shuffle=False} to stay aligned with it.

\textbf{Memory-bounded loader.} At $S=30$ the windows no longer fit comfortably 
in a Colab runtime. The rewritten 
loader makes two passes: the first counts the windows
each trace will produce, the second fills one pre-allocated \texttt{float32}
array and frees each trace as soon as it is windowed, loading train/val and
test as two independent calls and deleting the \texttt{train\_test\_split}
copy explicitly. Peak memory is roughly halved and the windows are identical.

\subsection{Cross-domain split}
Following the SHARP protocol the split is by environment, never random: $S1$
($S1a,S1b,S1c$) is used for training/validation and every other set is held out.
A random split would leak windows from the same person/room/day into both sides
and overestimate performance. Within $S1$ we keep $85\%$ for training and $15\%$
for validation, $2767$ / $489$ / $10{,}308$ windows for train / val / test at $S=340$ and
$31{,}103$ / $5489$ / $115{,}728$ at $S=30$. Grouping the four antennas collapses
the test windows to $2577$ and $28{,}932$ distinct physical time windows
respectively.

\section{Learning Framework}
\label{sec:learning_framework}

\subsection{Baseline CNN}
\label{sec:baseline}

\begin{figure}[t]
  \centering
  \includegraphics[width=\columnwidth]{SHARP_architecture_baseline.png}
  \caption{Baseline single-antenna architecture of
  SHARP reduced-Inception module~(\cite{sharp}, Fig.~4). \texttt{S2} denotes
  stride~2; every CONV is followed by a ReLU.}
  \label{fig:baseline_arch}
\end{figure}

The baseline reproduces the reduced-Inception module of SHARP (\cite{sharp},
Fig.~4), shown in \fig{fig:baseline_arch}: three parallel branches (max-pool,
strided conv, three stacked convs) turn the $1\times340\times100$ input into
feature maps of identical size $170\times50$, concatenated on the channel axis
($1{+}5{+}9=15$), reduced to $3$ channels by a $1\times1$ convolution, flattened
and classified by a dense layer after $\mathrm{Dropout}(0.2)$ leads to
$128{,}535$ parameters, exactly the count reported for the SHARP
baseline CNN. Training uses cross-entropy, Adam, mini-batches of $64$ and
early stopping, restoring the lowest-validation-loss weights.

Three optimizer schedules were compared with architecture, seed, batch
size and split held fixed, because their effect is counter-intuitive. The
fast schedule ($\text{lr}=10^{-3}$, patience~$7$,
budget $40$) stops at epoch~$13$ (best validation loss $0.993$) with the classic
overfitting signature: training accuracy climbs to $0.601$ while validation
accuracy plateaus near $0.52$. The slow schedule ($10^{-4}$,
patience~$5$, budget $100$) runs for $41$ epochs with the two curves almost on
top of each other and stops at a training accuracy of only $0.575$: the model has
not yet fitted its own training set. Reading that as underfitting, the
adopted schedule keeps $10^{-3}$ but raises patience to $12$: a plateau
no longer ends training prematurely (\fig{fig:training_curves}), which matters at stride~$30$, where each
epoch is an order of magnitude slower; on that data it reaches $0.750$ training
accuracy and stops at epoch~$27$.

\subsection{Contrastive extension: Supervised Contrastive Learning}
\label{sec:contrastive}

\subsubsection{Motivation and augmentations}
We use Supervised Contrastive Learning (SupCon)~\cite{supcon} to learn similar
representations for the same activity and different representations for
different activities, regardless of person, environment or antenna. Two
augmented views are created from each window using amplitude scaling
($\mathcal{U}(0.8,1.2)$), Gaussian noise ($\sigma=0.05$), circular time shifts
($\pm40$ samples), and time/Doppler masking ($40$ time samples and $15$
velocity bins). After pre-training, the encoder is frozen and a linear
classifier is trained on its output.

\subsubsection{Encoder and projection head}
The encoder extends the baseline's three-branch Inception block with batch
normalization, a $1\times1$ reduction to $32$ channels and a second
downsampling stage ($32\!\rightarrow\!64\!\rightarrow\!128$). Global average
pooling produces a $128$-dimensional representation $h$. A projection head
($128\!\rightarrow\!128\!\rightarrow\!128$) maps $h$ to a normalized vector
$\bm{z}$ for the SupCon loss. The head is removed after pre-training, so the
classifier uses $h$. The model has $130{,}952$ parameters.

\subsubsection{SupCon loss}
For each sample $i$, the loss pulls it closer to samples with the same label,
denoted by $P(i)$, and pushes it away from samples with different labels:
\begin{equation}
\label{eq:supcon}
\mathcal{L}=\frac{1}{|I|}\sum_{i\in I}\frac{-1}{|P(i)|}\sum_{p\in P(i)}
\log\frac{\exp(\bm{z}_i\!\cdot\!\bm{z}_p/\tau)}
{\sum_{a\neq i}\exp(\bm{z}_i\!\cdot\!\bm{z}_a/\tau)},
\end{equation}
where $I$ contains samples with a same-label partner and $\tau=0.07$. Unlike
SimCLR~\cite{simclr}, SupCon uses labels, so same-activity windows from
different environments are also treated as positive pairs.

\subsubsection{Training and evaluation protocol}
We use the same $S1$-based split as the baseline. The encoder and projection
head are pre-trained with Adam for up to $30$ epochs, using weight decay
$10^{-4}$ and early stopping. The linear probe freezes the encoder and trains a
$\mathrm{Linear}(128,5)$ classifier. Fine-tuning instead updates the full model
at learning rate $10^{-4}$. A t-SNE plot checks whether the learned groups
depend on activity rather than environment. Pre-training and probe learning
rates are $10^{-3}$ for non-overlapping windows and $10^{-4}$ for sliding
windows.

\subsection{Multi-antenna decision fusion}
\label{sec:fusion}
The dataset ships the four antenna streams separately, and both chains so
far discard that structure. SHARP keeps the per-antenna training convention but
fuses the four decisions at inference~\cite{sharp}; that step is reproduced here
as pure post-processing. For a group id $g$, let $A_g$ be the (up to four)
antenna windows carrying it and $\bm{p}_i=\mathrm{softmax}(f(\bm{x}_i))$ the class
probabilities of window~$i$. The fused decision is

\begin{equation}
\label{eq:fusion}
\hat{y}_g=\argmax_{c\in\{1,\dots,5\}}\ \frac{1}{|A_g|}\sum_{i\in A_g} p_{i,c},
\end{equation}

i.e.\ a soft vote, preferred to majority voting on the hard labels because
a confident antenna can outweigh two unsure ones and because it degrades
gracefully when a recording provides fewer than four streams. The reference paper
does not detail its own rule, so \eq{eq:fusion} is a standard instantiation
rather than a reproduction.

Two details make it correct: the group id must not encode the stream
index, so the four antennas collide onto one key, and the evaluation
\texttt{DataLoader} must not shuffle or the probabilities stop lining up with
the stored ids. Fusion also changes the unit of evaluation: one decision
per physical time window instead of one per antenna.
